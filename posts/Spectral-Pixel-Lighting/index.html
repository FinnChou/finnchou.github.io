光谱渲染：给一间像素小屋打光

用 C 语言逐波长计算一间像素小屋里的光：从光源光谱乘反射率的单点颜色讲起，依次加上提灯的衰减、遮挡、窗外的日光与天光、墙面间的反射和色调映射，配代码与渲染图，附交互演示。

光谱渲染：给一间像素小屋打光

在《『颜色』是什么》里，我们把 LED 的光谱乘以越橘与蒲公英的光谱反射率，再用等色函数积分，算出了它们在几种光下的颜色。有了那个实验，我们想把同样的计算从一个点推广到整个画面，于是开始用 C 语言写一个小小的渲染引擎。

后来机缘巧合，我们觉得搭一间 2D 的小屋、给它打光挺有意思，于是有了这篇文章。在这个引擎里，光从灯出发，照到地板、墙壁和家具上，按各自的光谱反射率反射出来，每个像素的颜色都由 400～700 nm 的光谱算出。光源光谱取自 CIE 的数据表，材料的反射率取自 KLUM 城市建材光谱库（Ilehag 等，2019），代码开源在 spectral-pixels。

下面先放演示，再从一个点的颜色讲起，每节只加一样东西：光随距离的衰减、遮挡、窗外的光、墙面间的反射，最后处理画面的明暗范围。各节合起来，就是演示里的小屋。

二、一个点的颜色

这一节先不管灯在哪：光从正上方均匀地照下来，处处一样亮，只看一个点。

光源与材料

演示里的光源，除蜡烛外都取自 CIE 的数据表。烛光主要来自火焰中炽热碳粒的热辐射，这里用 1900 K 的黑体代替。

材料取自 KLUM（Karlsruhe Library of Urban Materials），这是 Ilehag 等人 2018 年夏天在德国卡尔斯鲁厄室外实测的城市建材光谱库，共 181 个样本，波长 350～2500 nm，间隔 1 nm（Ilehag 等，2019）。演示选了其中 20 种木材、砖石与灰泥（陶瓦在演示里叫「陶土方砖」）1。

光谱乘反射率

设光源的相对光谱功率分布为 $P(\lambda)$，它在表面上产生的照度为 $E$，表面的光谱反射率为 $\rho(\lambda)$。表面按朗伯漫反射处理，从哪个方向看都一样亮，反射光的三刺激值为

\[X = E \sum_{\lambda} \hat{P}(\lambda)\, \rho(\lambda)\, \overline{x}(\lambda)\]

$Y$、$Z$ 把 $\overline{x}(\lambda)$ 换成 $\overline{y}(\lambda)$、$\overline{z}(\lambda)$ 即可。式中：

  • $\overline{x}(\lambda)$、$\overline{y}(\lambda)$、$\overline{z}(\lambda)$ 是 CIE 1931 标准观察者的等色函数；
  • $\hat{P}(\lambda)$ 是归一化后的光谱，满足 $\sum_\lambda \hat{P}(\lambda)\, \overline{y}(\lambda) = 1$，于是光谱只管颜色，强弱全交给照度 $E$2；
  • $\lambda$ 从 400 nm 到 700 nm 每 5 nm 取一点，共 61 点，范围之外等色函数的值已经很小。

这是《CIE-XYZ 表色系》里那个积分的离散形式，只是把光源拆成了光谱形状与照度两部分。

XYZ 还要换成屏幕上的 8 位 RGB：先按 IEC 61966-2-1 规定的矩阵转成线性 sRGB，超出 sRGB 色域、算出负值的分量截为 0，再按 sRGB 的传递函数编码成 0～255，大于 1 的值按 1 处理。画面很亮时还要多一步色调映射，留到第七节再讲。

下图是同一块红砖地板，先后由蜡烛与冷白 LED（CIE LED-B5）从正上方均匀地照着，照度相同。两盏灯的相关色温一低一高，是 1900 K 与 6598 K。下面三张图依次是光源的光谱、地板的反射率，以及两者相乘、小点脚下反射出来的光。

蜡烛
冷白 LED

同一块红砖地板，两盏灯的照度相同

烛光的能量越往长波越多，又正好落在红砖反射得多的长波段，反射光八成多在 600 nm 以上，砖是橙红色的；冷白 LED 在短波、中波也有不少能量，反射光摊得开，砖就淡得多，砖缝也成了灰色。画面不做白平衡，相当于把相机的白平衡固定在 D65（色适应见《白点切换》），灯光本身的颜色原样留在画面里。

颜色相同的两盏灯

逐波长计算的用处，在颜色相近的两盏灯上看得最清楚。蜡烛与高压钠灯（CIE HP1）的颜色几乎一样，色度坐标 $(x, y)$ 分别是 (0.538, 0.411) 与 (0.533, 0.415)；红砖在两盏灯下的视感反射率也几乎相同，是 23% 与 24%。颜色却不一样：

蜡烛
高压钠灯

同一块红砖地板，换成蜡烛与高压钠灯

红砖相差 $\Delta E_{00} = 5.7$，陶土方砖相差 9.0，是演示里 20 种材料中最大的（色差见《色差公式的演进》）。差别不在明暗，而在色相：钠灯下两者都更黄，彩度也更低。

原因在光谱上。高压钠灯在 400～700 nm 的能量，约一半挤在 575～605 nm 这 30 nm 里（图中的灰底），605 nm 以上不到四分之一；蜡烛在 605 nm 以上的能量将近四分之三。红砖的反射率从 500 nm 的 0.12 升到 650 nm 的 0.29，在那 30 nm 里是 0.23～0.26。于是钠灯下，红砖反射的光一半多来自这一段，颜色接近灯光本身；烛光在长波段更强，红砖在那里反射得也更多，就显得更红。只看灯的颜色，算不出这个差别。

先对波长求和

一个点往往同时被几盏灯照亮，各盏灯的贡献直接相加。记第 $l$ 盏灯的照度为 $E_l$，三刺激值为

\[X = \sum_{l} E_l \sum_{\lambda} \hat{P}_l(\lambda)\, \rho(\lambda)\, \overline{x}(\lambda)\]

直射光的照度 $E_l$ 只取决于灯的强度与几何：灯在哪、离这一点多远、光线与表面成多大角度、中间有没有东西挡着，都与波长无关。所以内层的求和可以单独拿出来：

\[\mathbf{T}_l(\rho) = \sum_{\lambda} \hat{P}_l(\lambda)\, \rho(\lambda)\, \big( \overline{x}(\lambda),\ \overline{y}(\lambda),\ \overline{z}(\lambda) \big)\]

$\mathbf{T}_l(\rho)$ 是材料 $\rho$ 在单位照度的光源 $l$ 下的三刺激值，上面两张图里小点脚下的颜色，就是 $\mathbf{T}$ 乘上照度。引擎里，材料存成一张反射率表，每行一种。设定光源光谱时先做归一化，再对表的每一行求和，存成这盏灯的一张小表 L->xyz：

static void integrate(const float *spd, const float *refl, float xyz[3])
{
    for (int c = 0; c < 3; c++) {
        float sum = 0;
        for (int k = 0; k < SPL_NW; k++) {
            sum += spd[k] * refl[k] * CMF[c][k];
        }
        xyz[c] = sum;
    }
}
/* … */
spl_status spl_light_set_spectrum(spl_engine *e, int l, const float spd[SPL_NW])
{
    /* … */
    float y = spectrum_luminance(spd);
    /* … */
    light *L = &e->lights[l];
    for (int k = 0; k < SPL_NW; k++) {
        L->spd[k] = spd[k] / y;
    }
    L->has_spectrum = 1;
    for (int r = 0; r < e->config.rows; r++) {
        integrate(L->spd, &e->reflectance[r * SPL_NW], &L->xyz[3 * r]);
    }
    return SPL_OK;
}

SPL_NW 是采样点数 61，e->config.rows 是反射率表的行数，CMF 是等色函数，spectrum_luminance() 求的是 $\sum P(\lambda)\,\overline{y}(\lambda)$。

光谱只出现在这张表里，往后各节要算的只剩照度 $E_l$。

三、提灯：照度随距离衰减

这一节的场景只有地板，没有墙，也没有物体。小点提着一盏蜡烛站在中央，灯离地 18 像素。

每个像素一个表面点

要算照度，先要知道每个像素看到的是空间里哪一点，那一点的表面朝哪个方向。小屋按斜俯视的平行投影画出：世界坐标 $(x, y, z)$（$x$ 向右，$y$ 朝画面下方、靠近观者，$z$ 朝上）的点画在屏幕的 $(x,\ y - z/2)$ 处，越高越靠上，近处的东西挡住远处的3。投影由场景代码 scene.c 完成，结果是每个像素一个表面点：

typedef struct {
    float p[3];  /* world position of the visible surface point */
    float n[3];  /* unit normal */
    int32_t row; /* reflectance row; outside the table (e.g. -1): no surface, transparent pixel */
    float tex;   /* texture shade, multiplies the reflectance */
} spl_surface;

row 是反射率表的行号，引擎只认这张表，不知道材料叫什么。tex 是纹理系数，乘在反射率上，砖面的斑驳、砖缝的阴影都靠它；它只按比例缩放反射率，不改变光谱的形状。窗洞处没有表面，row 为 −1。只有地板时，每个表面点都在 $z = 0$，法线朝上。

平方反比与余弦

提灯是点光源，照度为

\[E = \frac{I \cos\theta}{d^2}\]

$I$ 是灯的发光强度，$d$ 是灯到表面点的距离，$\theta$ 是表面法线与指向灯的方向之间的夹角。光从灯出发，摊在越来越大的球面上，所以与 $d^2$ 成反比；斜着照到表面上，同样的光摊得更开，所以再乘上 $\cos\theta$。几何因子就是 $\cos\theta / d^2$：

static float point_factor(const spl_engine *e, const spl_surface *s, const float q[3],
                          const float *nq, float step)
{
    float v[3] = { q[0] - s->p[0], q[1] - s->p[1], q[2] - s->p[2] };
    float d2 = dot3(v, v);
    if (!(d2 > 0)) {
        return 0;
    }
    float d = sqrtf(d2);
    float cos_s = dot3(s->n, v) / d;
    float cos_q = 1;
    if (nq) {
        cos_q = -dot3(nq, v) / d;
    }
    if (!(cos_s > 0 && cos_q > 0 && unobstructed(e, s->p, q, step))) {
        return 0;
    }
    return cos_s * cos_q / d2;
}

q 是灯的位置，v 是从表面点指向灯的向量，cos_s 就是 $\cos\theta$。nq 与 cos_q 留给面光源用，点光源传入 NULL；unobstructed() 判断中间有没有东西挡着，下一节再讲。$\cos\theta \le 0$ 说明灯在表面背后，照度为 0。

蜡烛

空地板上一盏烛光提灯，不计环境光

左图里，光在地面上形成一圈由亮到暗的光晕。右图是地面上的衰减：设灯高为 $h$，水平距离 $r$ 处 $d^2 = r^2 + h^2$、$\cos\theta = h/d$，于是 $E = Ih/d^3$，相对正下方是 $(h/d)^3$，比单纯的平方反比衰减得更快：水平距离等于灯高时，照度只剩正下方的 35%，单按平方反比还有 50%。图中的点是引擎算出的照度，都落在公式的曲线上。

四、遮挡与阴影

在空地板上摆几件物体：一段墙、一根石柱、一个木箱、一个木桶。

高度图

空间里哪里是实心的，用一张俯视的高度图描述：地面上每个位置 $(x, y)$ 记一个高度，低于它的部分是实心的。墙和石柱高 32，木桶 12，木箱 10。房间还有屋顶，在 32 处，只挡光、不画出来；窗洞是墙上的缺口，上下沿之间不挡光。这一节的场景是露天的。

static int solid(const spl_engine *e, float x, float y, float z)
{
    int i = (int)y * e->config.width + (int)x;
    if (z > e->ceiling) {
        return 1;
    }
    int in_gap = z > e->gaps[2 * i] && z < e->gaps[2 * i + 1];
    return z < e->heights[i] && !in_gap;
}
/* … */
static int unobstructed(const spl_engine *e, const float p[3], const float q[3], float step)
{
    float d[3] = { q[0] - p[0], q[1] - p[1], q[2] - p[2] };
    int n = (int)fminf(sqrtf(d[0] * d[0] + d[1] * d[1]) / step, 1e9f) + 2;
    float w = (float)e->config.width;
    float h = (float)e->config.height;
    for (int k = 1; k < n; k++) {
        float t = (float)k / n;
        float x = p[0] + d[0] * t;
        float y = p[1] + d[1] * t;
        if (!(x >= 0 && y >= 0 && x < w && y < h)) {
            return 1;
        }
        if (solid(e, x, y, p[2] + d[2] * t)) {
            return 0;
        }
    }
    return 1;
}

e->heights 是高度图，e->gaps 存每一格缺口的下沿与上沿，e->ceiling 是屋顶的高度。solid() 判断一个点是否在实心部分里：高于屋顶，或者低于这一格的高度、又不在缺口里。unobstructed() 把连线按水平距离分成若干段，每段不超过 step 个像素，点光源取半个像素；采样点一旦走出高度图的范围，后面就不会再被挡，直接算作照得到4。

同一盏提灯，同样几件物体；侧视图只是示意，取样实际密得多

左图不判断遮挡：物体照样画出来，光却穿过它们照到后面的地板上；物体背着提灯的一面，$\cos\theta \le 0$，是黑的。右图判断遮挡：石柱和墙比提灯高，背后完全照不到，影子一直拖到画面边缘；木箱和木桶比提灯矮，影子只拖出一段。影子的边缘是一级一级的锯齿：遮挡物本身按像素划分，点光源又没有大小，影子是硬的。

五、窗外的光：平行光与面光源

窗外的光也先单独看：又回到只有地板的场景。

太阳离得足够远，光线彼此平行，照度只取决于光线与法线的夹角：$E = E_\perp \cos\theta$，$E_\perp$ 是垂直于光线的平面上的照度。天光来自整片天空，在屋里，它只能从窗洞照进来，所以把窗洞当作亮度均匀的面光源：

\[E = L \int_A \frac{\cos\theta\, \cos\theta'}{d^2}\, \mathrm{d}A\]

$L$ 是窗洞的亮度，积分遍及窗洞 $A$ 上的每个小块 $\mathrm{d}A$；$d$ 与 $\theta$ 换成表面点到这个小块的距离与夹角，$\theta’$ 是窗洞法线与光线之间的夹角。算上遮挡，这个积分没有简便的解析式。引擎把窗洞分成 8×4 格，每格随机取一点当作一盏小点光源，32 个样本的平均乘以窗洞的面积，就是积分的估计，这种做法叫分层抽样。三种光源的几何因子都在 geometry() 里：

static float geometry(const spl_engine *e, const light *L, const spl_surface *s, int i)
{
    const shape *sh = &L->shape;
    if (sh->kind == POINT) {
        return point_factor(e, s, sh->pos, NULL, HARD_STEP);
    }
    if (sh->kind == DIRECTIONAL) {
        /* … */
        float reach = (float)(e->config.width + e->config.height);
        float cos_t = dot3(s->n, sh->pos);
        float far[3];
        for (int c = 0; c < 3; c++) {
            far[c] = s->p[c] + sh->pos[c] * reach;
        }
        if (!(cos_t > 0 && unobstructed(e, s->p, far, HARD_STEP))) {
            return 0;
        }
        return cos_t;
    }
    /* Area light: one sample per stratum, weighted by area. */
    float sum = 0;
    for (int a = 0; a < AREA_LONG; a++) {
        for (int b = 0; b < AREA_SHORT; b++) {
            int k = 2 * (a * AREA_SHORT + b);
            float fa = (a + jitter(i, k)) / AREA_LONG * 2 - 1;
            float fb = (b + jitter(i, k + 1)) / AREA_SHORT * 2 - 1;
            float q[3];
            for (int c = 0; c < 3; c++) {
                q[c] = sh->pos[c] + L->axis_long[c] * fa + L->axis_short[c] * fb;
            }
            sum += point_factor(e, s, q, L->normal, SOFT_STEP);
        }
    }
    return sum * L->area / (AREA_LONG * AREA_SHORT);
}

点光源一段就是第三节的 point_factor()。平行光一段里，sh->pos 是指向太阳的单位向量，cos_t 就是 $\cos\theta$，遮挡沿这个方向检查到 reach 远的地方。面光源一段里，sh->pos 是窗洞的中心，axis_long、axis_short 是长边与短边的一半，AREA_LONG、AREA_SHORT 是两个方向上的格数；jitter() 让样本在自己那一格里随机偏移5，point_factor() 传入窗洞的法线，乘上 $\cos\theta’$，L->area 是窗洞的面积。

天光：面光源

阳光是 CIE 照明体 D55；天光是相关色温 10000 K 的 CIE 日光，按 CIE 015:2018 的日光公式合成。面光源的位置与演示里的窗洞相同，在画面上方边缘外；两幅曝光相同，比演示低

六、墙面间的反射：环境光

到这里算的都是直射光。把场景围上三面墙、关上窗，就成了一间屋子。真实的屋子里，光在墙面、地面之间反复反射，所以灯照不到的角落并不是全黑的。

精确计算这些反射，要考虑每两个表面之间的相互照射。引擎用一个估计代替：设屋里各表面的平均反射率为 $\bar{\rho}$，直射照度的平均值为 $\bar{E}$。第一次反射后，各表面平均多出 $\bar{\rho}\bar{E}$ 的照度，第二次 $\bar{\rho}^2\bar{E}$，全部加起来是

\[E_\text{amb} = \bar{E} \left( \bar{\rho} + \bar{\rho}^2 + \cdots \right) = \bar{E}\, \frac{\bar{\rho}}{1 - \bar{\rho}}\]

在内壁是均匀漫反射面的积分球里，这个关系对每个波长都精确成立，因为球面任何一处反射出去的光，都会均匀地照亮整个内壁。屋子不是球，画面下方的那一面还是敞开的；引擎只把它当作估计，用视感反射率代替逐波长的反射率，给每个表面加上同样的 $E_\text{amb}$，光谱与这盏灯相同。下面是对一盏灯求 $\bar{E}$ 与 $\bar{\rho}$ 的循环：

double sum_g = 0;

int count = 0;
for (int i = 0; i < e->pixels; i++) {
    const spl_surface *s = &e->surfaces[i];

    sum_g += (double)g[i];
    /* The spectrum is normalized, so Y is the luminance reflectance. */
    sum_rho += (double)(s->tex * L->xyz[3 * s->row + 1]);
    count++;
}
if (count == 0) {
    continue;
}
float mean_rho = fminf((float)(sum_rho / count), RHO_MAX);
e->ambient[l] =
    e->ambient_k * L->strength * (float)(sum_g / count) * mean_rho / (1 - mean_rho);

e->pixels 是像素数，g 是这盏灯对各像素的几何因子，sum_g / count 是它在可见表面上的平均，乘以灯的强度就是 $\bar{E}$。$\bar{\rho}$ 取 L->xyz 的 $Y$ 分量乘以纹理系数再平均，即这些表面在这盏灯下的视感反射率。e->ambient_k 是环境光的总系数，演示里取 1，前面各节的图里取 06。

这个估计不考虑遮挡，也不考虑反射带来的颜色变化：真实的屋子里，红砖地面反射到墙上的光会偏红，这里则与灯光同色。Cohen 等人 1988 年的渐进式辐射度算法也用到这个关系，但只估计尚未分配出去的光能；这里用它代替全部的间接光。

七、明暗范围：曝光与色调映射

打开窗，阳光照进来，窗下光斑与墙角的亮度差得很远。8 位编码只能表示 0～1，超过 1 的分量只能按 1 处理，引擎因此在矩阵与编码之间加了两步：乘以曝光，再逐通道做色调映射：

static void encode(const float xyz[3], float k, uint8_t out[3])
{
    for (int c = 0; c < 3; c++) {
        out[c] = quantize(tonemap(fmaxf(k * dot3(XYZ_TO_RGB[c], xyz), 0)));
    }
}

k 是曝光；fmaxf(…, 0) 截掉负值，quantize() 按 sRGB 的传递函数编码成 8 位，这两步就是第二节的换算。色调映射用的是 Narkowicz 对 ACES 电影曲线的拟合：

\[f(x) = \frac{x\,(2.51x + 0.03)}{x\,(2.43x + 0.59) + 0.14}\]

$x$ 是乘以曝光后的线性分量。$x$ 很大时，$f(x)$ 趋于 $2.51/2.43 \approx 1.03$，再亮的光也被平滑地压到 1 附近。没有这一步，超出 1 的部分只能直接截断：

把各节合起来，就是开头的演示。渲染一幅画面，就是对每个像素把各盏灯的照度乘上 L->xyz 里对应的一行，相加，再换算到屏幕上：

float xyz[3] = { 0, 0, 0 };
for (int l = 0; l < e->config.lights; l++) {
    const light *L = &e->lights[l];
    if (!active(L)) {
        continue;
    }
    float g = e->geometry[(size_t)l * (size_t)e->pixels + (size_t)i];
    float illuminance = s->tex * (L->strength * g + e->ambient[l]);
    for (int c = 0; c < 3; c++) {
        xyz[c] += illuminance * L->xyz[3 * s->row + c];
    }
}
encode(xyz, e->exposure, out);

s 是第 $i$ 个像素的表面点，g 是第三到五节算出的几何因子，乘上灯的强度 L->strength 就是直射照度；e->ambient[l] 是第六节的环境光，encode() 是第七节的换算。

光谱只出现在 L->xyz 这一处；平方反比与余弦、遮挡、平行光、面光源、环境光，算的都是与波长无关的照度。蜡烛与钠灯照在红砖上的差别，就来自这张表。

简化也有不少：表面都是朗伯漫反射，环境光只是房间平均的估计，光谱只算 400～700 nm，遮挡物按像素划分。
